> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reorganise rangka-apps into contract 0001's modules and apps, and add the modules and the apps `jasa_proyek` and `fnb_cabang` that cover both pilots' day-one lists, with a demo site per app that seeds and runs against the kernel.

**Architecture:** `.rk` metadata only. Modules hold models, rules, flows, roles, print formats and imports. Apps compose modules and add menus, dashboards and onboarding. The kernel's contract 0001 side does not exist yet, so the plan uses an interim layout that today's kernel and both validators accept unchanged (below). Keys from kernel streams that have not merged sit in sidecar files so that today's validation stays at 0 errors. Cross-record logic (allocation, stock posting, moving average, recipe explosion, revisions) is declared as named hooks whose exact semantics `docs/kernel-hooks.md` fixes for the kernel to implement.

**Tech Stack:** `.rk` strict YAML (schema 0.4 + 0.5 kinds), CEL, rangka-os kernel (`rangka validate|migrate|seed|serve`), `tools/rangka_validate.py`, Python 3 stdlib for scripts and the integration test.

**Spec:** `rangka-os/docs/superpowers/specs/2026-11-03-first-pilots-design.md` and program plan `rangka-os/docs/superpowers/plans/2026-11-03-pilot-program.md` (stream S8, Fixed interfaces), contract `0001-modules-and-apps.md`, draft contracts 0007 (approvals), 0008 (print), 0009 (numbering), 0010 (multi-org), 0012 (imports), 0013 (money) in the kernel streams' worktrees.

## Global Constraints

- `.rk` is strict YAML: no yes/no/on/off, no unquoted leading-zero numbers, `${ENV}` quoted inside flow maps, first line `# yaml-language-server: $schema=https://rangka-os.github.io/rangka-os/schema/0.4/<kind>.json` (0.5 for the new kinds `print`, `import`).
- Code, comments, docs in English. UI text Bahasa Indonesia first, sentence case, "kamu". Rupiah `Rp 1.250.000`, dates `27 Okt 2026`.
- IDR amounts are `currency` (whole rupiah, every compute wrapped in `round()`); foreign amounts only via `money` (sidecar until S8a lands); never `float` for money. Rates and quantities may be `float`.
- Money, stock and document numbers are never decided by an LLM. Submitted documents change only through cancel + amend.
- Apps define no models. Module names, app names and model names exactly as in the program plan's Fixed interfaces.
- No real customer data: fictional names only (`PT Contoh …`, `Tahu Contoh …`), `.test` domains, NPWP `0000000000000000`-style placeholders.
- Every task ends with `scripts/validate.sh` printing `0 errors` for the Python and Go validators.

## Layout (interim, rulings)

```
modules/<m>/app.rk                  0.4 kind app (contract 0001: becomes module.rk, kind module)
modules/<m>/models|roles|flows/     as today
modules/<m>/print/<name>.rk + .html kind print (0.5, S3; ignored by today's loader)
modules/<m>/imports/<name>.rk       kind import (0.5, S7; ignored by today's loader)
modules/<m>/experimental/<model>.rk keys awaiting a kernel stream: {model, approvals, naming, fields, defaults}
apps/<a>/app.rk                     0.4 kind app: requires modules, menu, dashboards; no models/
apps/<a>/template.rk                0.4 kind template: roles, home, onboarding, connectors
apps/<a>/dashboards/ roles/
examples/sites/<site>/              demo sites (kopi-senja, demo-jasa, demo-fnb)
examples/fixtures/<site>/           their seed data
scripts/catalogue.sh                build/catalogue/<name> -> ../../modules/<name> | ../../apps/<name>
scripts/validate.sh                 both validators on build/catalogue for every example site
scripts/check_experimental.py       sidecars name existing models, fields and roles
tests/day_one.py                    integration test against a live kernel
docs/kernel-hooks.md                semantics of every hook the modules declare
```
- `user` moves to the kernel per 0001, but the kernel has no built-in `user` model yet. It sits in an interim module `users` that is deleted when 0001's kernel side lands.
- A site's `config.apps` must list apps **and** every module they require (today's `missing_dependency` rule). Kernel 0001 will install modules itself.
- Name collisions in `build/catalogue` (a module and an app with the same name) are an error in `catalogue.sh`.

## Review Focus

- **Same Moka export twice / overlapping days:** the import's `key` is `[Date, Receipt Number, Item, Variant]` scoped `per: outlet`, and `outlet_sales` is created as a draft, so stock moves only on submit. Pinned in Task 9 (import file) and Task 11 (second upload → `duplicate`, skipped while S7 has not merged).
- **Payment larger than outstanding / USD payment on an IDR invoice:** payment rules reject `allocated_total > amount` and any allocation row with `amount > outstanding`. The `payments.allocate` hook re-checks against stored invoices and converts at the payment's rate. Pinned in Task 6 and Task 11.
- **Sales that push stock below zero:** `stock.post_moves` never refuses. The `stock_move.negative` flag and the `stock_negative_alert` flow notify `head_office`, and the `fnb_cabang` dashboard lists balances < 0. Pinned in Task 8 and Task 11.
- **PPN on a non-PKP org:** `ppn_applies` false → `ppn` 0 and `grand_total = dpp`. Pinned in Task 3's REST check in Task 11.
- **DP deducted twice / retention billed twice:** rules `down_payment <= dp_invoice.dpp` and the retention invoice's `retention_of` must be submitted and not cancelled. Pinned in Task 3.

## Model reference (decisions; tasks implement exactly these)

Notation: `field:type[->target] (flags)`. `req` required, `ro` read_only, `list` in_list, `c=` compute, `d=` default.

**contacts**
- `customer`: customer_name:data(req,list), city:data(list), address:text, phone:phone, email:data, npwp:npwp, payment_days:int(d='30'), credit_limit:currency, outstanding:currency(ro,list), contacts:table->contact_person. naming `CUST-{####}`. Rule npwp_16 as today.
- `vendor`: vendor_name:data(req,list), city, address, phone, email, npwp, payment_days:int(d='30'), outstanding:currency(ro,list), contacts:table->contact_person. naming `VND-{####}`.
- `contact_person` (is_child): person_name:data(req), position:data, phone:phone, email:data, is_primary:check.

**catalogue** (stocked = `kind` material, good or product without a recipe; decided in the stock hook, no field)
- `uom`: uom_name:data(req,list,unique). naming `UOM-{###}`; title uom_name. Fixture rows: Pcs, Kg, Gram, Karung, Liter, Hari, Jam, Orang-hari, Unit, Paket.
- `item`: item_name:data(req,list), sku:data(unique,list), kind:select(service|good|material|product, req, list, d="'good'"), stock_uom:link->uom(req), sales_uom:link->uom, rate:currency(list) (price), standard_cost:currency, notes:text. naming `BRG-{####}`.
- `uom_conversion`: item:link->item(req,list), uom:link->uom(req,list), factor:float(req,list) (1 uom = factor × item.stock_uom). Rule factor > 0. naming `KONV-{####}`. Used as the `packing` link on purchase and stock lines.
- `price_list`: list_name:data(req,list), customer:link->customer (optional), valid_from:date, valid_until:date, items:table->price_list_item. naming `HRG-{###}`.
- `price_list_item` (child): item:link->item(req), uom:link->uom, rate:currency(req).

**outlets**: `outlet`: outlet_name:data(req,list), code:data(unique,list), city:data(list), address:text, is_head_office:check, active:check(d='true'). naming `OUT-{##}`.

**users** (interim): `user` as today plus email:data.

**tax_id**: `tax_code`: code:data(req,unique,list), tax_name:data(req,list), kind:select(ppn|pph23, list), rate:percent(req,list), dpp_ratio:data (e.g. "11/12"), active:check. naming `PJK-{##}`. Fixtures: PPN 12% (dpp 11/12), PPh 23 2%.

**currency**: `currency`: code:data(req,unique,list) (ISO), currency_name:data(list), symbol:data. `exchange_rate`: currency:link->currency(req,list), rate_date:date(req,list), rate:float(req,list) (IDR per unit). Sidecars add `currency`/`rate`/`money` fields to quotation, sales_invoice, payment, purchase_order, vendor_bill.

**quotation**
- `quotation` (submittable): customer:link(req,list, peek npwp,payment_days), contact_person:data, subject:data(req) ("Perihal"), rfq_ref:data ("No. RFQ"), rfq_date:date, quotation_date:date(d=today(),req,list), valid_until:date(d=`quotation_date + duration(30)`, relative_to quotation_date), revision:int(d='0',ro,list), items:table->quotation_item(min_rows 1), subtotal:currency(c=sum), discount_amount:currency(d='0'), dpp:currency(c=`subtotal - discount_amount`), ppn_applies:check(d='true'), ppn:currency(c=`ppn_applies ? round(dpp * 11 / 12 * 12 / 100) : 0`), grand_total:currency(c=`dpp + ppn`,list), payment_terms:text, delivery_terms:text, outcome:select(open|accepted|lost, d="'open'", list, chip), lost_reason:text(depends_on outcome=='lost'), notes:text. naming `QUO-{YYYY}-{#####}`. Rules: valid_until >= quotation_date; discount_amount <= subtotal. Action `new_revision` hook `quotation.revise` if `docstatus == 1 && outcome == 'open'`; action `make_order` hook `orders.from_quotation` if `docstatus == 1 && outcome == 'accepted'` (declared in quotation module so the action shows; hook implemented with orders).
- `quotation_item` (child): item:link->item(req), description:text, qty:float(d='1'), uom:link->uom(d=item.sales_uom), rate:currency(d=item.rate), discount:percent(d='0'), amount:currency(c=`round(qty * rate * (1 - discount / 100))`).
- Sidecar: approvals `[{name: manager_approval, on: submit, approvers: [sales_manager], label: Persetujuan manajer}]`, naming `{series: quotation, pattern: "QUO-{YYYY}-{#####}"}`, ppn_applies default `org.pkp`, money fields.

**orders**: `customer_order` (submittable): customer:link(req,list), quotation:link->quotation(list), po_number:data(req,list) ("No. PO pelanggan"), po_date:date(req), work_order:data, site:data ("Lokasi kerja"), start_date, end_date:date, items:table->customer_order_item(min_rows 1), subtotal:currency(c=sum,list), invoiced_amount:currency(ro), notes. naming `SO-{YYYY}-{#####}`. **invoicing**
- `sales_invoice` (submittable): kind:select(regular|down_payment|retention, d="'regular'", list, chip), customer:link(req,list, peek outstanding,payment_days,npwp), customer_order:link->customer_order, project:link->project, acceptance:link->acceptance, po_number:data(d=customer_order.po_number), outlet:link->outlet (optional; kept for crm.mark_won), posting_date:date(d=today(),req,list), due_date:date(d=`posting_date + duration(customer.payment_days)`, relative_to), items:table->sales_invoice_item(min_rows 1), subtotal:currency(c=sum), discount_amount:currency(d='0'), dp_invoice:link->sales_invoice (depends_on kind=='regular'), down_payment:currency(d='0'), dpp:currency(c=`subtotal - discount_amount - down_payment`), ppn_applies:check(d='true'), tax_rate:percent(d='12'), ppn:currency(c=`ppn_applies ? round(dpp * 11 / 12 * tax_rate / 100) : 0`), grand_total:currency(c=`dpp + ppn`,list), retention_percent:percent(d='0'), retention_amount:currency(c=`round(dpp * retention_percent / 100)`), retention_of:link->sales_invoice (depends_on kind=='retention'), pph23_applies:check(d='false'), pph23_rate:percent(d='2'), pph23_amount:currency(c=`pph23_applies ? round(dpp * pph23_rate / 100) : 0`), amount_due:currency(c=`grand_total - retention_amount - pph23_amount`,list) ("Tagihan bersih"), paid_amount:currency(ro), outstanding:currency(c=`amount_due - paid_amount`,list), notes. naming `INV-{YYYY}-{#####}` (kopi-senja keeps it via config). on_submit `ledger.post_receivable`, on_cancel `invoicing.reverse_receivable`.

**payments**
- `payment` (submittable): direction:select(receive|pay, d="'receive'", req, list, chip), customer:link->customer (depends_on direction=='receive'), vendor:link->vendor (depends_on direction=='pay'), payment_date:date(d=today(),req,list), method:select(transfer|cash|giro|other, d="'transfer'"), reference:data ("No. bukti/transfer"), amount:currency(req,list) (cash received/paid), allocations:table->payment_allocation, allocated_total:currency(c=`allocations.map(a, a.amount).sum()`), withheld_total:currency(c=`allocations.map(a, a.withheld).sum()`), unallocated:currency(c=`amount - allocated_total`,list), notes. naming `PAY-{YYYY}-{#####}`. on_submit `payments.allocate`, on_cancel `payments.unallocate`.
